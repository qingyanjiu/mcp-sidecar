## 1. 系统全景

系统由 **两个部署单元 + 三类外部依赖** 组成：

- **mcp-sidecar**：Java / Spring Boot 3 / Spring AI。同时承担聊天网关、MCP 服务端、场景动作调度三个角色。
- **agentic-app**：Python / FastAPI / LangGraph。作为聊天后端和 MCP 客户端。
- **外部依赖**：Platform 平台（业务数据 + 登录态）、RAGFlow（知识库）、LLM 服务（OpenAI 兼容 API）。

```text
     ┌─────────────────────────────┐                                      ┌─────────────────────────────┐
     │ 浏览器聊天前端              │                                      │ UE 场景页面                 │
     │ /llm/chat · /llm/gen_doc    │                                      │ /ws/scene                   │
     └─────────────────────────────┘                                      └─────────────────────────────┘
                    │                                                                    │
                    └──────────────────────────────────┬─────────────────────────────────┘
                                                       ▼  2222 公网（唯一 publish）

  ┌──────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
  │ mcp-sidecar（Spring Boot 3 / Spring AI）                                                                         │
  │ EndpointPortGuardFilter — 按监听端口隔离可访问路径                                                               │
  │                                                                                                                  │
  │   ┌────────────────────────────────────────────────┐      ┌────────────────────────────────────────────────────┐ │
  │   │ 2222 公网（唯一 publish）                      │      │ 2223 内网（仅 expose）                             │ │
  │   │ AuthHandshakeInterceptor（握手取 token）       │      │ MCP Streamable HTTP — 17 端点 / 113 工具           │ │
  │   │ ProxyWebSocketHandler（鉴权+限流+代理）        │      │ 接收 agent tools/call（Mcp-Session-Id）            │ │
  │   │ LLMChatLimiter（并发信号量）                   │      │ SceneDispatcher / SceneSessionRegistry             │ │
  │   │ SceneWebSocketHandler（hello / action_result） │      │ PlatformApiCallServiceImpl / RagflowApiClient      │ │
  │   └────────────────────────────────────────────────┘      └────────────────────────────────────────────────────┘ │
  │                                                                                                                  │
  │ Actuator :9970（仅容器内健康检查，不 publish）                                                                   │
  │                                                                                                                  │
  └──────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
                               │                                                         │
                               ▼  WS 代理                                                ▼  HTTP + 服务账号 token

      ┌────────────────────────────────────────────┐          ┌────────────────────────────────────────────────────┐
      │ agentic-app :8001                          │          │ Platform :9500（业务数据 / 登录态）                │
```

### 1.1 组件职责

| 组件 | 职责 | 对外端口 |
|---|---|---|
| 浏览器聊天前端 | 发起 `/llm/chat`、`/llm/gen_doc` WebSocket，展示流式回答 | — |
| UE 场景页面 | 连接 `/ws/scene`，上报场景状态，执行动作帧并回执 | — |
| **mcp-sidecar** | 聊天鉴权/限流/WS 代理；17 个 MCP 服务端；场景动作调度 | 2222（发布）、2223（仅内网）、9970（仅容器内） |
| **agentic-app** | LangGraph 推理、意图路由、MCP 客户端、流式回答 | 8001（仅内网） |
| Platform 平台 | 业务数据 API、用户登录态校验 | 9500（sidecar 访问） |
| RAGFlow | 知识库检索 | 9380（sidecar 访问） |
| LLM 服务 | 大模型推理 | 由 `LLM_BASE_URL` 决定 |
| Redis | compose 中预置的可选缓存服务（`--profile redis`） | —（当前未使用） |

### 1.2 端口矩阵

| 端口 | 是否发布到宿主机 | 允许的路径 | 用途 |
|---|---|---|---|
| `2222` | **是**（`docker compose` 唯一 publish 的端口） | `/llm/**`、`/ws/**` | 聊天 WebSocket、文档生成、场景页面 WebSocket |
| `2223` | 否，仅 `expose` 到容器网络 | `/mcp/**` | Python agent 调用 MCP 工具 |
| `9970` | 否，仅容器内 | `/actuator/**` | 健康检查，供 Docker healthcheck 使用 |
| `8001` | 否，仅 `expose` | `/chat/**`、`/gen_doc/**`、`/asr/**` | agentic-app 内部服务，只允许 sidecar 访问 |

端口隔离由 `EndpointPortGuardFilter` 执行（`server`、`local` profile 均启用）：

- 2222 上访问 `/mcp/**` → 直接 404；
- 2223 上访问 `/llm/**`、`/ws/**` → 直接 404；
- 9970 等其它管理端口不受该过滤器影响。

### 1.3 部署拓扑

```text
宿主机 / 公网
├── 浏览器聊天前端 ── WS ──▶ 127.0.0.1:2222   /llm/chat、/llm/gen_doc
├── UE 场景页面     ── WS ──▶ 127.0.0.1:2222   /ws/scene
│
└── Docker 网络 ai-agenic-network
    ├── mcp-sidecar
    │   ├── publish 2222 → /llm/**、/ws/**        （宿主机唯一入口）
    │   ├── expose  2223 → /mcp/**                （只允许 agent 访问）
    │   └── expose  9970 → /actuator/**           （仅容器内 healthcheck）
    ├── agentic-app（expose 8001）
    │   ├── /chat/**、/gen_doc/**、/asr/**         （只允许 sidecar 访问）
    │   ├── sidecar ──WS 代理──▶ agent            （sidecar 是 WS 客户端）
    │   └── agent ──MCP tools/call──▶ sidecar:2223
    └── redis（--profile redis，可选；当前未使用）

sidecar ──HTTP──▶ Platform :9500 / RAGFlow :9380
agent   ──HTTPS─▶ LLM 服务
```

> 宿主机只暴露 2222；`agentic-app` 的 8001 和 sidecar 的 2223、9970 都不 publish。
> 本地调试若要让宿主机直连 agent，可临时取消 compose 中 `agentic-app` 的 `ports` 注释（只绑 `127.0.0.1`）。

## 2. 核心数据链路

系统有四条主链路：

| 链路 | 发起方 | 协议 / 端口 | 接收方 | 用途 |
|---|---|---|---|---|
| A. 聊天问答 | 浏览器 | WebSocket / 2222 | sidecar → agent | 对话、文档生成 |
| B. MCP 查询 | agent | MCP Streamable HTTP / 2223 | sidecar → Platform | 实时业务数据查询 |
| C. 场景动作下发 | agent | MCP Streamable HTTP / 2223 | sidecar → UE 页面 | 切楼层、聚焦、显示等 |
| D. 场景状态同步 | UE 页面 | WebSocket / 2222 | sidecar | 会话归档、场景状态、动作回执 |

### 2.1 A：聊天问答链路

```text
  浏览器                          sidecar:2222                          Platform:9500                       agent:8001
  │                               │                                     │                                   │
  │─ WS /llm/chat?token&userId ──▶│                                     │                                   │
  │                               │                                     │                                   │
  │                               │ ┌─ 提取 token / userId / sessionId ─┐                                   │
  │                               │ └───────────────────────────────────┘                                   │
  │                               │                                     │                                   │
  │                               │──────── GET /llmChat/auth ─────────▶│                                   │
  │                               │                                     │                                   │
  │                               │───── {status:1, data:200|401} ─────◀│                                   │
  │                               │                                     │                                   │
  │ ※ data≠200：返回 UNAUTHORIZED 并关闭                                │                                   │
  │                               │                                     │                                   │
  │                               │ ┌─ 限流 tryToChat ─┐                │                                   │
  │                               │ └──────────────────┘                │                                   │
  │                               │                                     │                                   │
  │ ※ 3 秒内拿不到许可：返回 TOO_MANY_REQUESTS                          │                                   │
  │                               │                                     │                                   │
  │                               │──────────────────── WS /chat/{userId}/{sessionId} ─────────────────────▶│
  │                               │                                     │                                   │
  │                               │─────────────────────── 101 Switching Protocols ────────────────────────◀│
  │                               │                                     │                                   │
  │────────── 用户消息 ──────────▶│                                     │                                   │
  │                               │                                     │                                   │
  │                               │─────────────────────────────── 原样转发 ───────────────────────────────▶│
  │                               │                                     │                                   │
  │                               │                                     │      ┌─ LangGraph 推理 / 调 MCP ─┐│
  │                               │                                     │      └───────────────────────────┘│
  │                               │                                     │                                   │
  │                               │─────────────────────────────── 流式回答 ───────────────────────────────◀│
  │                               │                                     │                                   │
  │────────── 流式回答 ──────────◀│                                     │                                   │
  │                               │                                     │                                   │
  │──────────── 关闭 ────────────▶│                                     │                                   │
  │                               │                                     │                                   │
  │                               │───────────────────────────────── 关闭 ─────────────────────────────────▶│
  │                               │                                     │                                   │
  │                               │ ┌─ completeChat 释放许可 ─┐         │                                   │
  │                               │ └─────────────────────────┘         │                                   │
```

关键点：

- 浏览器原生 WebSocket 不能设置自定义请求头，token 优先从 `Authorization` 取，没有则回退到 query `token`（`AuthHandshakeInterceptor`）。
- 平台 `/llmChat/auth` 的鉴权结果在响应的 **`data` 字段**（HTTP 状态通常都是 200）：`200` 表示 token 有效且 `userId` 匹配，`401` 表示未登录或 `userId` 不匹配。sidecar 只认 `data=200`，不能只看 HTTP 状态。
- 并发限制是进程内 `Semaphore`（默认 `limitSize: 10`），每个 WS 连接占一个许可，断开时按用户计数释放。
- sidecar 是 **WS 客户端**，agent 是 **WS 服务端**；sidecar 只做透传，不解析业务消息。

### 2.2 B：MCP 平台业务查询链路

```text
  agent (MCP Client)                    sidecar:2223                                Platform:9500
  │                                     │                                           │
  │──────────── initialize ────────────▶│                                           │
  │                                     │                                           │
  │─── Mcp-Session-Id + serverInfo ────◀│                                           │
  │                                     │                                           │
  │─── tools/list + Mcp-Session-Id ────▶│                                           │
  │                                     │                                           │
  │─────────── 工具定义列表 ───────────◀│                                           │
  │                                     │                                           │
  │─── tools/call + Mcp-Session-Id ────▶│                                           │
  │                                     │                                           │
  │                                     │ ┌─ 路由到 @McpTool ─┐                     │
  │                                     │ └───────────────────┘                     │
  │                                     │                                           │
  │ ※ 仅当内存中无平台 token，或 token 已过期（30 分钟）                            │
  │                                     │                                           │
  │                                     │─────── GET /noLogin/getLoginInfo ────────▶│
  │                                     │                                           │
  │                                     │─────── ssl / sslType / publicKey ────────◀│
  │                                     │                                           │
  │                                     │──────── POST /login（RSA 加密） ─────────▶│
  │                                     │                                           │
  │                                     │───────────── {data:{token}} ─────────────◀│
  │                                     │                                           │
  │                                     │ ┌─ 缓存平台 token ─┐                      │
  │                                     │ └──────────────────┘                      │
  │                                     │                                           │
  │                                     │─────── GET/POST 业务接口 + Bearer ───────▶│
  │                                     │                                           │
  │                                     │────────── {status, msg, data} ───────────◀│
  │                                     │                                           │
  │──────── tools/call result ─────────◀│                                           │
```

关键点：

- sidecar 用 **服务账号** 登录 Platform，平台 token 缓存在 `AbstractApiCallService.tokenMap`，默认 30 分钟有效；业务工具调用与用户登录态无关。
- Platform 平台开启 `sslLogin=on` 时，登录参数用 `/noLogin/getLoginInfo` 返回的公钥做 RSA 加密（`RSA/ECB/PKCS1Padding`）。
- 每个 MCP 端点独立维护 `Mcp-Session-Id`；`/mcp/scene` 额外要求逐请求注入 `X-Session-Id`（见 2.3）。
- `mcp.mock` 机制仍保留，但当前所有工具的 `@MockData` 注解均已注释，实际全部走真实平台接口。

### 2.3 C：场景动作下发链路

```text
  UE 场景页面                           sidecar                               agent
  │                                     │                                     │
  │─────────── WS /ws/scene ───────────▶│                                     │
  │                                     │                                     │
  │───── hello{sessionId,userId} ──────▶│                                     │
  │                                     │                                     │
  │                                     │ ┌─ SceneSessionRegistry.bind ─┐     │
  │                                     │ └─────────────────────────────┘     │
  │                                     │                                     │
  │─────────── scene_state ────────────▶│                                     │
  │                                     │                                     │
  │                                     │ ┌─ 更新场景状态 ─┐                  │
  │                                     │ └────────────────┘                  │
  │                                     │                                     │
  │ ※ 聊天链路已建立，LLM 决定下发场景动作                                    │
  │                                     │                                     │
  │                                     │──── tools/call + X-Session-Id ─────◀│
  │                                     │                                     │
  │                                     │ ┌─ SceneDispatcher.dispatch ─┐      │
  │                                     │ └────────────────────────────┘      │
  │                                     │                                     │
  │ ※ 未连接 / 未知动作 / 破坏性动作：立即返回错误，不挂起                    │
  │                                     │                                     │
  │─────── action 帧 + actionId ───────◀│                                     │
  │                                     │                                     │
  │ ┌─ 执行动作 ─┐                      │                                     │
  │ └────────────┘                      │                                     │
  │                                     │                                     │
  │──────── action_result{ok} ─────────▶│                                     │
  │                                     │                                     │
  │                                     │─── 工具结果（成功 / 失败原因） ────▶│
  │                                     │                                     │
  │                                     │                                     │ ┌─ LLM 组织自然语言回答 ─┐
  │                                     │                                     │ └────────────────────────┘
  │                                     │                                     │
  │ ※ 回答经 /llm/chat 链路回到浏览器聊天窗口                                 │
```

关键点：

- 会话路由键是 `X-Session-Id`，由 agent 从聊天入口的 `sessionId` 透传，**不能由 LLM 填**。缺省时 `singleSessionFallback=true` 只在恰好一条连接时兜底，多条连接直接拒绝。
- `SceneDispatcher` 同步等待 `action_result`，默认超时 `scene.action-timeout-ms=15000`。Python 侧客户端超时必须大于该值。
- 同一 `sessionId` 新连接会顶掉旧连接；`scene.redispatch-on-reconnect=true` 时，在途动作会重发给新连接（动作需幂等）。
- 破坏性动作（`scene_set_area_state`、`scene_set_inspection_state`）由 `scene.destructive-enabled=false` 挡住，当前阶段不下发。
- 页面未连接时**立即失败**，不挂起等待——避免 LLM 白等十几秒。

MCP 客户端连接方式（Python 侧 `mcp_client/mcp_server_config.yaml`）：

```yaml
mcp_base_url: http://mcp-sidecar:2223/mcp
mcp_servers:
  local:
    transport: streamable_http
    url: /personStatus
  # ... 其余端点同理
```

> agent 与 sidecar 在同一容器网络时用服务名 `mcp-sidecar:2223`；agent 跑在宿主机时改成宿主机可达 IP，端口仍是 `2223`。
> `/mcp/scene` 另有 `SCENE_MCP_URL` 环境变量可单独覆盖。

## 5. 安全边界与已知限制

1. **端口隔离是 MCP 的主要防线。** `/mcp/**` 不发布到宿主机，只允许同一 Docker 网络的 agent 访问；公网 2222 上访问 `/mcp/**` 直接 404。
2. **`/llm/chat`、`/llm/gen_doc` 有应用层鉴权。** token + `userId` 交给 Platform `/llmChat/auth` 校验，失败返回 `UNAUTHORIZED` 并关闭连接。
3. **`/ws/scene` 当前没有应用层鉴权**（协议设计为靠 `sessionId` 归档）。它只接受页面主动上报的 `hello` / `scene_state` / `action_result`，不能直接触发动作；但暴露在 2222 公网上，仍是已知待补项。
4. **MCP 端点本身没有应用层鉴权。** 安全边界依赖“端口不发布 + 容器网络可达性”，不要把这些端点映射到宿主机或公网。
5. **Platform 使用服务账号调用业务接口。** 服务账号凭据在 `PlatformApiCallServiceImpl` 中配置；平台 token 只缓存在 sidecar 内存，不落盘。
6. **场景动作有白名单和破坏性闸门。** 只有 `SceneActions.ALL` 中的 19 个动作可下发；破坏性动作默认关闭。
7. **单会话兜底只适合联调。** 多用户部署必须由 agent 逐请求注入 `X-Session-Id`，否则会拒绝或推错页面。
8. **Redis 当前未接入业务。** compose 中的 redis 是预留服务（`--profile redis`），sidecar 代码没有使用；健康检查已关闭避免日志膨胀。
