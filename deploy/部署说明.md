# 部署说明

`deploy/` 是 mcp-sidecar 的运行时目录：整个目录挂载到容器的 `/app`，容器入口执行
`docker-start.sh` 里的 `java -jar mcp-sidecar.jar`。镜像只装 JRE 和运行环境，
业务产物以宿主机这份目录为准，改完 `restart` 即可生效，不用重建镜像。

## 目录结构

```text
deploy/
├── mcp-sidecar.jar          # 编译产物；容器实际运行的就是它（git 忽略，部署前必须存在）
├── application-server.yml   # profile=server 的配置（${ENV} 占位，仓库版本不含明文）
├── docker-start.sh          # 容器入口脚本
├── merge-env.sh             # 把两份 *.example 的键幂等合并进根目录 .env
├── nginx.conf               # 宿主机 Nginx 参考配置（反代 /llm/、/ws/scene）
└── logs/                    # 运行日志（git 忽略，首次启动自动创建）
```

## 端口与访问边界

| 端口 | 监听 / 暴露 | 用途 |
|---|---|---|
| 2222 | 宿主机 `127.0.0.1`（由 Nginx 反代） | `/llm/chat`、`/llm/gen_doc`、`/ws/scene` |
| 2223 | 仅容器网络（`expose`，不 publish） | `/mcp/**`，供 agentic-app 调用，需 `MCP_API_KEY` |
| 9970 | 仅容器内 | `/actuator/health` |
| 8001 | 仅容器网络 | agentic-app，由 sidecar 代理 |

对外只需要开放 Nginx 的 80/443。不要把 2222 改成 `0.0.0.0:2222` 发布到局域网/公网。

## `.env` 的两部分

`.env` 由两份模板组合而成，部署时合并成一个文件，放在 `docker-compose.yml` 同目录（仓库根目录）：

| 部分 | 来源文件 | 内容 |
|---|---|---|
| 非敏感配置 | `env.docker.example` | 镜像 tag、代码目录、端口、运行环境、启动开关、路由与灰度、Redis 连接、LLM 参数、MCP 超时、知识库检索参数等 |
| 敏感信息 | `.env.example` | 平台 / RAGFlow 地址与凭据、平台登录、数据库 / Redis / SSL / Kafka、跨域白名单、知识库直连、`MCP_API_KEY` 等 |

组合命令：

```bash
# 在 docker-compose.yml 同目录（仓库根目录）执行
{
  cat env.docker.example          # 非敏感部分
  echo
  echo "# 以下是敏感信息，仅部署使用，请勿提交到代码仓库或者外传。"
  cat .env.example                # 敏感部分
} > .env
chmod 600 .env
# 再编辑 .env，把占位值换成真实值
```

约定：

- 顺序固定为「非敏感部分 → 敏感部分」。两份模板有同名键（`REDIS_*`、`KB_*`），
  dotenv 的规则是后出现的覆盖前面的，因此敏感部分的值最终生效；
- 敏感部分只能留在部署机：不提交 Git、不贴到工单/聊天、不打进镜像或 jar；
- 整个 `.env` 已被 `.gitignore` 忽略；
- `AGENTIC_CODE_DIR` / `MCP_CODE_DIR` 是部署机上的绝对路径，换机器部署时要改；
- 改了 `.env` 要 `docker compose up -d` 重建容器，`restart` 不会重新读取。

也可以执行 `bash deploy/merge-env.sh --write` 做增量合并：它从两份模板和
`docker-compose.yml` 收集键，只补 `.env` 里缺失的，不覆盖已有值。首次从空文件开始时，
上面的组合命令更直观。

## 首次部署

### 0. 前置条件

- Docker + Docker Compose v2（`docker compose version`）
- 两个镜像已导入本机：
  ```bash
  docker load -i mcp-sidecar.tar
  docker load -i agentic-app.tar
  ```
- agentic-app 代码目录存在（`AGENTIC_CODE_DIR`，默认值见 `env.docker.example`）
- 打包 sidecar 需要 JDK 17 + Maven

### 1. 放好 jar

```bash
# 在 mcp-sidecar 仓库根目录
mvn clean package
cp target/mcp-sidecar.jar deploy/
```

没有独立 `mvn` 时，用 IntelliJ 自带的 Maven 面板执行 `clean` / `package`，产物同样在 `target/`。

> Compose 把 `deploy/` 挂到 `/app`，会覆盖镜像里自带的 `/app`，所以宿主机这里必须有 jar；
> 否则容器启动时报找不到 jar。

### 2. 生成 `.env`

按上一节「`.env` 的两部分」把 `env.docker.example` 和 `.env.example` 组合成
`docker-compose.yml` 同目录的 `.env`，再把占位值换成真实值。必填项：

| 变量 | 说明 |
|---|---|
| `MCP_API_KEY` | `openssl rand -hex 32` 生成；sidecar 与 agentic-app 必须一致；为空时 `/mcp/**` 全部 401 |
| `MCP_PLATFORM_BASE_URL` / `PLATFORM_LOGIN_*` | 平台地址与登录凭据 |
| `MCP_RAGFLOW_BASE_URL` / `MCP_RAGFLOW_API_KEY` | RAGFlow 地址与 API Key |
| `OPENAI_API_KEY`（或 `LLM_API_KEY`） | agentic-app 的模型密钥 |
| `KB_BASE_URL` / `KB_API_KEY` | 知识库直连；两者都留空才回落到 sidecar 的 `/mcp/knowledge` |

注意事项：

- `MCP_RAGFLOW_BASE_URL` 必须是 **sidecar 容器内可达** 的地址，不能写 `localhost` / `127.0.0.1`
  （那是容器自己）。同 Docker 网络用 `http://ragflow:9380`；RAGFlow 在宿主机用
  `http://host.docker.internal:9380`；否则填局域网 IP。
- 如果只想在已有 `.env` 上补漏，先执行 `bash deploy/merge-env.sh` 预演，
  确认后加 `--write`；它只补缺失键，不覆盖已有值。

如果连自带的 redis 容器，`REDIS_HOST=redis` 并加 `--profile redis` 启动。

### 3. 启动

```bash
docker compose config -q      # 校验 compose 文件（-q 不打印变量值）
docker compose up -d
docker compose ps
docker compose logs -f mcp-sidecar
```

启动顺序是 agentic-app 先起（模型加载慢），sidecar 只等它 `service_started`，不等 `healthy`。

### 4. 验证

```bash
# 容器内健康检查（9970 不发布到宿主机）
docker exec mcp-sidecar curl -fsS http://127.0.0.1:9970/actuator/health

# /mcp/**：不带 key 应为 401，带正确 key 应能完成 initialize
docker exec mcp-sidecar curl -isS -X POST http://127.0.0.1:2223/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H 'Authorization: Bearer <MCP_API_KEY>' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"healthcheck","version":"1.0"}}}'
```

### 5. 配置 Nginx

```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/mcp-sidecar.conf   # 路径按发行版调整
sudo nginx -t
sudo nginx -s reload
```

`deploy/nginx.conf` 是参考配置：静态目录（`D:/...`）、`/platform/`、`/dahua-icc/`、
`/api/` 等 upstream 都是原环境的值，迁移时按实际替换，用不到的 location 可以删掉。

## Nginx 参考配置要点

- 对外只暴露 `/llm/` 和 `/ws/scene`，反代到 `127.0.0.1:2222`。因为 2222 只绑回环，
  Nginx 必须和 sidecar 在同一台机器上（或另做 SSH 隧道/端口转发）。
- WebSocket 必须转发 `Upgrade` / `Connection`，并延长读写超时；`proxy_buffering off`
  保证流式输出不被缓冲。
- 浏览器的 WebSocket API **不能自定义请求头**。示例用两个 `map` 从 `USER_TOKEN` cookie
  取 token，握手时注入 `Authorization: Bearer ...`。这两个 `map` 必须放在 `http {}` 级，
  不能放进 `server {}`。
- 前端也可以改用 query 参数 `?token=...`（sidecar 支持），两种方式二选一，不要让两处的值不一致。
- `gzip_static on` 需要磁盘上存在预压缩的 `.gz` 文件；没有就不必保留该指令。

## 凭证放哪里

真实凭据统一写在项目根目录的 `.env`（与 `docker-compose.yml` 同目录），该文件由两份模板
组合而成，并已被 `.gitignore` 忽略。敏感信息部分来自 `.env.example`，只能留在部署机，
具体见「`.env` 的两部分」。

- Docker：Compose 自动读取根目录 `.env`，通过 `environment` 注入容器；
- 本地 IDE：`application.yml` 里的 `spring.config.import` 会读取项目根目录 `.env`；
- 敏感信息写进 `.env` 的敏感部分，不要写回模板或配置文件；
- `deploy/application-server.yml` 已入库的版本只保留 `${...}` 占位，真实值不要写回去；
- 真实凭据不要写进 `src/main/resources`：那里的文件会被打进 jar。

## MCP 内网端点鉴权（SEC-08）

`/mcp/**` 要求应用层 API Key，`MCP_API_KEY` 未配置时**拒绝所有请求（401）**：

```bash
openssl rand -hex 32          # 生成一个 key，写进根目录 .env 的 MCP_API_KEY
```

- `docker-compose.yml` 会把同一个 `MCP_API_KEY` 同时注入 `mcp-sidecar` 和 `agentic-app`；
  Python 侧 MCP client 必须带上 `Authorization: Bearer <key>` 或 `X-MCP-API-Key: <key>`。
- 容器内 `MCP_INTERNAL_ADDRESS` 固定为 `0.0.0.0`（compose 已注入），否则 `agentic-app`
  无法通过 `mcp-sidecar:2223` 访问；2223 不发布到宿主机，不代表对公网开放。
- 本地非容器运行时保持默认 `127.0.0.1`，2223 只在回环地址监听。

## 改了东西怎么生效

```bash
# 只改配置
vim deploy/application-server.yml
docker compose restart mcp-sidecar

# 重新打包后换 jar（不用重建镜像）
#   用 Maven 或 IntelliJ 打包
cp target/mcp-sidecar.jar deploy/
docker compose restart mcp-sidecar

# 改 .env 或 compose 的环境变量映射
docker compose up -d mcp-sidecar     # 必须重建容器，restart 不会重读 .env

# 换 profile（默认 server）
SPRING_PROFILES_ACTIVE=local docker compose up -d mcp-sidecar
```

## 配置生效顺序

Spring Boot 默认配置位置（后者覆盖前者）：

```text
classpath:/ → classpath:/config/ → file:./ → file:./config/
```

`deploy/application-server.yml` 挂载后在容器里是 `/app/application-server.yml`（即 `file:./`），
已经优先于 jar 内那份，不需要再建 `config/` 子目录。Dockerfile 里的 `/app/config/`
是镜像内默认位置，被卷挂载覆盖后一般不再使用。

## 常见问题

- **容器报找不到 jar**：`deploy/mcp-sidecar.jar` 不存在，或 `MCP_CODE_DIR` 指错了目录。
- **`/mcp/**` 一直 401**：`MCP_API_KEY` 为空，或 sidecar 与 agentic-app 两边值不一致。
- **经 Nginx 的 WebSocket 401**：没有注入 `Authorization`（cookie 名不是 `USER_TOKEN`、
  `map` 放错层级），或 token 本身失效。
- **知识库 Connection refused**：`MCP_RAGFLOW_BASE_URL` 写成了 `localhost` / `127.0.0.1`。
- **改了 `.env` 不生效**：用了 `restart`；应使用 `docker compose up -d`。
- **`deploy/` 被清空**：容器里 `/app` 就是空的，`java -jar` 会直接报错；重新放入 jar 和配置。
